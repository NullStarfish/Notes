

> [!abstract] 核心理解
> 动态规划把问题拆成可复用的子问题，用**状态**描述子问题，用**状态转移**组合子问题的答案，再按照依赖关系求值。
>
> 对递归算法而言，可以把它理解成：将递归调用树中代表同一个子问题的节点合并，让每个状态的结果只计算一次。

本文沿着“递归 → 状态 → 0/1 背包 → 空间压缩 → DAG 与调度”的顺序理解 DP。代码使用 Python；背包例子统一假设容量为非负整数，物品重量为正整数，允许不选任何物品。

## 1. 递归、分治和动态规划是什么关系？

一个问题可以写成：

$$
F(s)=\operatorname{Combine}\bigl(F(s_1),F(s_2),\ldots,F(s_k)\bigr)
$$

其中 $s$ 表示当前子问题，$s_1,\ldots,s_k$ 是它依赖的子问题。

**递归**是实现方式：函数调用自身，沿着上述关系求解。**分治**是问题分解思想：拆成较小问题，求解后合并。**动态规划**则强调设计状态、建立转移，并复用子问题的结果。它们并不互斥，记忆化递归就是动态规划的一种实现。

| 方式 | 如何求解子问题 | 遇到相同子问题时 |
| --- | --- | --- |
| 朴素递归 | 按调用关系向下展开 | 通常重新计算 |
| 经典分治，如归并排序 | 拆分为通常不重叠的子问题再合并 | 通常没有大量重复结果需要复用 |
| 自顶向下 DP（记忆化搜索） | 递归求值并缓存 | 直接读取缓存 |
| 自底向上 DP（递推填表） | 先算依赖，再算当前状态 | 复用表中已经算出的值 |

### 1.1 从斐波那契看重复子问题

$$
F(0)=0,\quad F(1)=1,\quad F(n)=F(n-1)+F(n-2)
$$

求 $F(5)$ 时，$F(4)$ 和 $F(3)$ 都会涉及 $F(2)$。朴素递归反复展开这些调用，时间是指数级的；缓存后，每个 $F(k)$ 只求一次，时间降为 $O(n)$（这里按一次加法为常数成本分析）。

```python
from functools import cache

@cache
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
```

也可以按 $0,1,2,\ldots,n$ 的顺序递推：

```python
def fib_bottom_up(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]
```

两者使用同一个递推关系，只是求值顺序不同。DP 也可以用于计数、可行性判断，并不限于最优化问题。

## 2. 状态：哪些历史可以合并？

我在讨论中的理解是：

> 子问题变成了一种状态，可以被 $i,j$ 唯一确定。

这个方向是对的，但“不能唯一确定就是普通递归”需要修正：**普通递归也可以用参数唯一确定子问题。是否唯一确定，并不是递归与 DP 的分界。** 如果缓存使用的参数不足以确定子问题，缓存反而可能产生错误。

状态设计真正需要回答的是：

> 给定这些状态变量后，求解这个子问题还需要知道哪些历史信息？

如果还需要知道某个未记录的信息，就说明状态不充分。例如，“容量还剩 3”无法确定 0/1 背包的答案，因为还要知道哪些物品可以选。

可以把状态看成对历史 $h$ 的压缩：

$$
s=\phi(h)
$$

不同历史只有在对应的后续可行选择、收益规则都一致时，才能共享同一个“后续最优值”。若采用前向 DP，把多段历史汇聚到同一状态，还需要正确保留累计收益：例如相同状态下只保留最大的累计价值。

**状态不一定要记录完整路径，但必须保留影响后续决策的信息。** 数组下标只是状态的存储方式；状态也可以是区间、集合、树节点，或多个变量组成的元组。

## 3. 最优子结构：为什么能只保留子问题的最优值？

以到达某级台阶的最小费用为例：从地面 $0$ 出发，每次向上走 1 或 2 级，落到第 $i$ 级支付 $c_i$。

定义 $D(i)$ 为到达第 $i$ 级的最小总费用，则：

$$
D(0)=0,\quad D(1)=c_1
$$

$$
D(i)=\min\{D(i-1),D(i-2)\}+c_i,\quad i\ge 2
$$

任意到达 $i$ 的路径，最后一步一定来自 $i-1$ 或 $i-2$。如果某条最优路径来自 $i-1$，它到达 $i-1$ 的前半段也必须最优：否则可以替换为更便宜的前半段，使总费用更小，与原路径最优矛盾。

这就是**最优子结构**。它允许每个子问题只保留最优值，而不保留所有候选路径。

这里替换成立的前提是：替换前半段后，后半段仍然可行，费用的组合方式也不变。若“之前是否使用过优惠券”会影响后续费用，就需要把优惠券状态加入 DP 状态。

## 4. 0/1 背包：从状态到转移

有 $n$ 件物品，物品 $i$ 的重量为 $w_i$，价值为 $v_i$。每件物品最多选一次，在总重量不超过 $W$ 的条件下最大化总价值。

贯穿全文的例子：

| 物品 | 重量 $w_i$ | 价值 $v_i$ |
| --- | --- | --- |
| A | 2 | 3 |
| B | 3 | 4 |
| C | 4 | 5 |
| D | 5 | 8 |

背包容量 $W=8$。直接枚举有 $2^n$ 种选或不选的组合。

### 4.1 状态定义

$$
D(i,j)=\text{只允许从前 }i\text{ 件物品中选择，总重量不超过 }j\text{ 时的最大价值}
$$

- $i$：允许使用的物品范围，不是已经选了几件。
- $j$：这个子问题的容量上限，不是填表过程中某个背包持续变化的剩余容量。
- $D(i,j)$：最优价值，不是已经使用的重量。

在递归分支中，选中某物品后，传给子问题的 $j-w_i$ 确实可以理解为剩余容量。但在整张 DP 表中，每一列 $j$ 表示一个不同容量限制的子问题。

### 4.2 按照“选不选第 $i$ 件”划分所有方案

**不选第 $i$ 件：** 只能从前 $i-1$ 件中选，容量仍然是 $j$，得到 $D(i-1,j)$。

**选择第 $i$ 件：** 要求 $j\ge w_i$。拿走它后，其他物品只能从前 $i-1$ 件中选，容量限制变为 $j-w_i$，得到 $D(i-1,j-w_i)+v_i$。

因此：

$$
D(i,j)=
\begin{cases}
D(i-1,j), & j<w_i,\\
\max\{D(i-1,j),\ D(i-1,j-w_i)+v_i\}, & j\ge w_i.
\end{cases}
$$

两类方案覆盖全部可能性；取最大值便得到当前状态的最优值。两个分支的物品范围都缩小为 $i-1$，保证物品 $i$ 不会再次被选择。

边界条件为：

$$
D(0,j)=0,\qquad D(i,0)=0
$$

这里允许空集且物品重量为正，所以没有可选物品或容量为零时，答案都是零。

### 4.3 完整表格与原讨论中的纠正

| 前 $i$ 件物品 / 容量 $j$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 无 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| A | 0 | 0 | 3 | 3 | 3 | 3 | 3 | 3 | 3 |
| A、B | 0 | 0 | 3 | 4 | 4 | 7 | 7 | 7 | 7 |
| A、B、C | 0 | 0 | 3 | 4 | 5 | 7 | 8 | 9 | 9 |
| A、B、C、D | 0 | 0 | 3 | 4 | 5 | 8 | 8 | 11 | 12 |

> [!important] $D(3,8)=9$，$D(4,8)=12$
> 前三件物品中，B+C 的重量为 7、价值为 9；A+B+C 重量为 9，超重。只有加入 D 后，B+D 才能达到重量 8、价值 12。

最后一个格子的计算是：

$$
\begin{aligned}
D(4,8)
&=\max\{D(3,8),D(3,8-5)+8\}\\
&=\max\{9,4+8\}=12.
\end{aligned}
$$

这里同时引用容量为 8 和容量为 3 的子问题，并不是把一个背包从容量 8 改成容量 3 后继续填写整张表。

### 4.4 二维实现：容量正序、倒序都可以

```python
def knapsack_2d(items, W):
    n = len(items)
    dp = [[0] * (W + 1) for _ in range(n + 1)]

    for i, (weight, value) in enumerate(items, start=1):
        for j in range(W + 1):
            dp[i][j] = dp[i - 1][j]
            if j >= weight:
                dp[i][j] = max(
                    dp[i][j],
                    dp[i - 1][j - weight] + value,
                )
    return dp[n][W]
```

计算第 $i$ 行时，只读取上一行。同一行各列之间没有值的依赖，所以 $j$ 可以正序、倒序，甚至在保存上一行的前提下并行计算。

时间为 $O(nW)$，空间为 $O(nW)$。这里 $W$ 是数值而不是编码它所需的位数，所以该算法属于**伪多项式时间**：当 $W$ 很大时，表格仍然可能无法承受。

## 5. 从二维到一维：压缩的是存储

### 5.1 先保留新旧两行

由于当前行只依赖上一行，不需要保存全部历史行：

```python
def knapsack_two_rows(items, W):
    prev = [0] * (W + 1)
    for weight, value in items:
        curr = prev.copy()
        for j in range(weight, W + 1):
            curr[j] = max(prev[j], prev[j - weight] + value)
        prev = curr
    return prev[W]
```

空间降为 $O(W)$，新旧两行仍在不同数组中，容量正序计算没有问题。

### 5.2 原地更新：为什么 0/1 背包要倒序？

如果连 `curr` 都省掉，用同一个数组保存新旧行：

```python
def knapsack_01(items, W):
    dp = [0] * (W + 1)
    for weight, value in items:
        for j in range(W, weight - 1, -1):
            dp[j] = max(dp[j], dp[j - weight] + value)
    return dp[W]
```

处理物品 $i$ 之前，`dp[j]` 表示 $D(i-1,j)$；处理完该物品后，它才表示 $D(i,j)$。**物品维度的语义仍然存在，只是由外层循环隐含表达。**

倒序更新到容量 $j$ 时：

- 大于 $j$ 的位置已经是当前行的新值。
- 小于等于 $j$ 的位置仍是上一行的旧值。
- 因为 $w_i>0$，所以 $j-w_i<j$，读取 `dp[j-weight]` 得到的仍是 $D(i-1,j-w_i)$。

因此每次原地更新都与二维转移一致。时间仍为 $O(nW)$，空间为 $O(W)$。

### 5.3 正序为什么会重复使用同一件物品？

只有一件物品，重量 2、价值 3，容量为 6。初始 `dp` 全为零。

| 正序更新位置 | 读取的值 | 写入结果 | 实际含义 |
| --- | --- | --- | --- |
| $j=2$ | `dp[0]=0` | `dp[2]=3` | 使用一次 |
| $j=4$ | 本轮刚更新的 `dp[2]=3` | `dp[4]=6` | 使用两次 |
| $j=6$ | 本轮刚更新的 `dp[4]=6` | `dp[6]=9` | 使用三次 |

而倒序先计算 $j=6$，此时 `dp[4]` 还是零，所以得到 3；接着计算 $j=5,4,3,2$，整个过程中读取的都是上一行的值，最终各个能容纳该物品的容量位置都为 3。

> [!tip] 区分三个层次
> 1. **状态含义**：$D(i,j)$ 究竟代表哪个子问题？
> 2. **逻辑依赖**：它要读取哪些状态的答案？
> 3. **存储与执行**：这些答案放在哪里，什么时候会被覆盖？
>
> 容量倒序是这一维原地实现为了保留旧值而采用的顺序，不是二维背包状态定义本身的要求。

## 6. 完全背包：为什么反而要正序？

完全背包允许每种物品无限次使用。仍定义 $D(i,j)$ 为使用前 $i$ 种物品、总重量不超过 $j$ 的最大价值。

如果选一种物品 $i$，剩下的问题**仍然允许选择物品 $i$**，因此在 $j\ge w_i$ 时：

$$
D(i,j)=\max\{D(i-1,j),D(i,j-w_i)+v_i\}.
$$

与 0/1 背包相比，关键变化是右侧第二项从第 $i-1$ 行变为第 $i$ 行。

```python
def knapsack_unbounded(items, W):
    dp = [0] * (W + 1)
    for weight, value in items:
        for j in range(weight, W + 1):
            dp[j] = max(dp[j], dp[j - weight] + value)
    return dp[W]
```

正序时，较小容量已经更新为当前行的值，恰好允许重复使用当前物品。

| 问题 | 选择当前物品后引用的状态 | 一维原地容量顺序 |
| --- | --- | --- |
| 0/1 背包 | $D(i-1,j-w_i)$，上一行 | 倒序，保护旧值 |
| 完全背包 | $D(i,j-w_i)$，当前行 | 正序，复用新值 |

不要只背“0/1 倒序、完全正序”；先判断转移需要旧行还是新行，再推导顺序。

## 7. DAG 视角：递归树合并为状态依赖图

对于本文这类无环递推，如果状态 $v$ 的计算需要状态 $u$，约定画边 $u\to v$，即**依赖状态指向使用者**。

例如两个不同调用都需要 $F(3)$ 时，递归调用树会出现两个 $F(3)$ 节点；按状态合并后，图中只保留一个 $F(3)$，让多个使用者共享其结果。

0/1 背包中的边为：

$$
(i-1,j)\to(i,j)
$$

$$
(i-1,j-w_i)\to(i,j),\quad j\ge w_i.
$$

沿边 $i$ 严格增加，所以不会有环。按 $i=0,1,\ldots,n$ 填表就是一个合法拓扑序。记忆化递归则从目标状态出发，先递归算完依赖，再返回当前状态的结果。

注意：递归调用从“当前问题”走向“依赖子问题”，其箭头方向与这里的依赖边方向相反。两种画法都可以，但必须说明方向。

DAG 最短路径也有同样结构：

$$
d(v)=\min_{(u,v)\in E}\{d(u)+w(u,v)\}.
$$

设置源点距离为 0，其余为 $+\infty$，按拓扑序处理即可。

“按拓扑序一次计算”适用于无环状态依赖。更广义的 DP（例如某些无限时域 Bellman 方程）可能涉及循环依赖，需要迭代求解，不能直接套用这个模型。

## 8. 与硬件、存储复用和并行调度的联系

### 8.1 工作量与关键路径

在二维或双行 0/1 背包中，上一行完成后，当前行各容量的计算彼此独立。

在每个状态计算耗时为常数、拥有足够处理器、忽略存储与通信成本的理想模型下，$W\ge1$ 时：

$$
T_1=\Theta(nW),\qquad T_\infty=\Theta(n),\qquad
\frac{T_1}{T_\infty}=\Theta(W).
$$

$T_1$ 是总工作量，$T_\infty$ 是依赖图最长路径对应的时间。实际加速还会受内存带宽、同步和处理器数量限制。

### 8.2 原地复用增加了覆盖约束

二维转移需要的是：

$$
\text{new}[j]=\max\{\text{old}[j],\text{old}[j-w_i]+v_i\}.
$$

把 `new` 与 `old` 放到同一数组后，更新较大容量 $j$ 的操作必须先读完旧的 `dp[j-weight]`，然后才允许较小容量的更新覆盖它。这是存储复用引入的 **WAR（Write After Read，写后于读）反依赖约束**。

若正序更新，大容量读到小容量刚写入的新值，就产生了当前行之间的 RAW（Read After Write）数据流，计算语义变为允许重复使用当前物品。

倒序循环是一种简单可靠的合法调度，但不能因此推断所有容量必须严格串行。给定物品重量 $w_i$，覆盖约束连接的是间隔 $w_i$ 的容量位置；不同余数链在适当调度下仍有并行空间。双行存储则更直接地避免这种覆盖约束，使行内并行更容易实现。

因此，这里体现的是**存储量、并行性与调度复杂度之间的权衡**。可以与 [[Loop Ordering]]、[[Tiling]]、[[并发与内存带宽]] 对照理解。

## 9. 做一道 DP 题时的推导顺序

1. **明确目标**：求最优值、方案数，还是可行性？约束是“不超过”还是“恰好”？
2. **用一句完整的话定义状态**：写清变量含义、允许使用的资源，以及值代表什么。
3. **检查状态是否充分**：相同状态下，还会因为未记录的历史导致不同答案吗？
4. **划分决策并推导转移**：例如选或不选，检查是否覆盖全部方案。
5. **设置边界与不可达值**：区分合法的零与不可达状态。
6. **确定依赖和计算顺序**：保证每个状态读取的是它真正需要的答案。
7. **先验证清晰实现，再压缩空间**：压缩后重新检查新旧值与覆盖关系。
8. **分析复杂度**：通常是“状态数 × 每个状态枚举的决策数”；也要注意容量数值可能很大。

例如“恰好装满”的最大价值背包，不能把所有容量都初始化为 0。应令容量 0 的价值为 0，其余容量为 $-\infty$，表示尚不可达，再通过合法转移更新。

DP 与贪心也要区分：DP 比较各个必要子问题中的候选决策；贪心直接做出某个选择，需要额外证明这种选择不会损害全局最优。例如面值 1、3、4 凑 6，优先拿最大面值会得到 4+1+1，而最优方案是 3+3。

## 10. 复习自测与后续路线

- 为什么普通递归也能用参数唯一描述子问题，却仍可能重复计算？
- 为什么 $D(3,8)=9$ 而不是 12？为什么 $j$ 不是填表过程中的单一剩余容量？
- 为什么二维 0/1 背包可以正序遍历容量，一维原地实现却通常倒序？
- 一维数组删掉了物品下标后，物品范围的信息保存在哪里？
- 如果问题改成完全背包，转移方程中的哪一个行号改变了？
- 为什么节省存储可能增加执行顺序约束？

沿着原讨论继续学习，可以依次研究：

1. **DAG 最短路与最长路**：巩固状态依赖和拓扑顺序。
2. **区间 DP**：用区间端点定义状态，理解按区间长度递增计算。
3. **Bellman 最优性原理**：进一步理解状态充分性、最优子结构与 [[RL]] 中价值函数的关系。
